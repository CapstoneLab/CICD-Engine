# 전체 검사 후 선택 검사 — 정책 1.3.1

사용자 확인: 최초 전체 검사는 취약점으로 배포가 차단되더라도 검사 자체가 정상 완료되면 인정한다.

- 사용자와 저장소를 기준으로 최초 전체 검사 완료 이력을 서버 DB에서 확인한다. 브랜치/커밋 변경만으로 전체 검사를 다시 강제하지 않는다. URL의 대소문자, .git 및 끝 슬래시 차이를 정규화한다.
- 완료 이력이 없으면 최초 요청이 일부 항목만 포함해도 전체 16개 카탈로그 항목을 적용한다. 두 스캐너의 성공, 전체 선택 목록, 검사 커밋 및 최종 판정 기록이 있어야 완료 이력으로 인정한다. 검사 도구 오류나 중단은 인정하지 않는다. 배포 성공은 조건이 아니다.
- 이후에는 요청한 CWE/카탈로그 key만 검사한다. 선택하지 않은 항목은 점수·승인·차단 이유에 포함하지 않는다. Secret(CWE-798)도 필수 항목이 아니다.
- Secret을 선택하지 않으면 Gitleaks를 건너뛴다. Secret만 선택하면 Semgrep을 건너뛴다. 나머지는 고정된 Semgrep 규칙 중 선택 CWE에 해당하는 규칙만 실행한다. 선택 CWE용 규칙이 전혀 없으면 검사 불가를 명시적으로 보고한다.
- 빈 선택 목록은 기존 API 계약대로 전체 검사를 의미한다. 잘못된 선택 key는 API에서 거절한다.
- 서버는 작업 생성과 엔진 claim 시점에 범위를 확인한다. metadata의 requested_selected_items는 최초 요청, selected_items는 실제 범위이며 scan_mode(full/selected), initial_full_scan_required로 판단 근거를 남긴다.
- 실행 격리, 토큰 보호, 요청 커밋 일치, 스캐너 오류 처리, 선택 범위 안의 위험도 보존 및 등급별 판정은 유지한다. 선택 검사 점수는 선택 범위의 점수다.

검증: 엔진 118개 테스트, 별도 PostgreSQL을 사용하는 백엔드 34개 테스트 통과. 실제 Semgrep에서 전체 검사에 포함되는 CWE-502가 XSS 선택 검사에서는 제외되는지 별도 합성 저장소로 확인했다.

실제 반영: 백엔드·엔진 `selected-policy-20261115` 이미지 적용 완료. 반영 후 DB 검사 이력 조회, 선택 항목 계약, 미선택 Secret 판정 제외, 공개 HTTPS health를 확인했다. 롤백 컨테이너 접미사는 `20261115-095751`이다.
